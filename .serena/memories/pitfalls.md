# Pitfalls
- iCloud duplicates: project lives on iCloud-synced Desktop; files like `page 2.tsx`, `api 2.ts`, `module 2.ts`, `* 2.test.ts` appear (74 identical copies removed in commit a941400, 2026-11-04; they reappear while the repo stays on iCloud). They are stale copies — never edit/import them; search results may show both. `tsconfig` only ignores `.next/**/* ?.ts`.
- Never run `npm run build` while the user's `npm run dev` may be running (both use `.next/`; the dev server dies). Ask first.
- CAPTCHA widget hosts (`CAPTCHA_CSP` in `modules/captcha/domain/captcha.ts`) are in `frame-src` / `connect-src` of storefront AND admin (panel key check). A new CAPTCHA provider needs its hosts there, else the widget is silently blocked and protected forms fail with `captcha_required`.
- Prod `litestream` runs as uid 1000 (= app `node` user) so the WAL/-shm files it may create stay writable for the app; `data-init` (busybox) chowns the fresh volume first because the app now starts after litestream. Litestream covers only `nova.db`, not `/data/uploads`.
- Storefront CSP `connect-src` / `frame-src` include tracking vendor hosts from `TRACKING_CSP` (consent/domain/tags.ts); a vendor whose beacons go to an unlisted host is silently blocked.
- `globals.css` must keep `@import "tailwindcss" source("..")` (scan src/ only): default root scan watches `.next/dev/logs` (written every request by Next 16) → endless dev reloads / e2e hangs.
- `npm run dev` and local `docker compose` share `data/nova.db`: never run both (SQLite locks over Docker Desktop file sharing are unreliable). After schema-changing `db:*` commands restart the dev server.
- Production without SESSION_SECRET/SECRETS_MASTER_KEY/CRON_SECRET → `ConfigError` at startup. `SECRETS_MASTER_KEY` must stay the same across moves, else sealed SMTP/AI/marketplace keys are unreadable.
- Standalone tracing: runtime fs paths built from `process.cwd()` / variables must carry `/* turbopackIgnore: true */` (see `src/server/env.ts`, `FsObjectStorage`), else Next copies the whole project (incl. `data/`, `.env*`) into `.next/standalone`. Packages imported by `scripts/*.mjs` inside the container must be in `serverExternalPackages`.
- Client IP = `X-Real-IP` (set by Caddy); the app container must never publish a port in production (header would be spoofable). Local Docker has no Caddy → all clients share one rate-limit IP.
- SSRF: `SafeFetcher` DNS-resolves every hop and refuses private IPs (app shares the Docker network with unauthenticated Kafka REST). Keep it; tests inject a resolver as 2nd ctor arg.
- SQLite ≥3.51: correlated subquery `ORDER BY` can't reference outer columns; keep outer refs in `WHERE`.
- `schema.sql` is fully re-runnable (tables, indexes, triggers all `IF NOT EXISTS`; catalog rows upsert) → `db:schema:*` adds new tables to an existing DB, but column changes don't apply (need `ALTER TABLE`). Keep new DDL idempotent.
- Outgoing mail = shop SMTP account (`modules/mail`, panel Entegrasyonlar › E-posta). Every send goes through `SmtpMailSender`, which writes `mail_deliveries` (panel "Son gönderimler") — background sends (reset mail in `after()`) are only visible there. SMTP failures → MailErrors only via `classifySmtpFailure` (stage + reply); transport errors must never include the sent command (AUTH carries the password). Panel "Parolamı unuttum" e-mails the reset link (identity `RequestPasswordReset`, run in `after()` for no enumeration); raw tokens never go to DB/outbox. Without SMTP the link is logged only when not production. Invite links are still shown to the admin. Gmail needs an app password. Many VPS block outbound port 25 → use 465/587.
- İYS and Paraşüt clients follow the docs but are tested only against fakes: before going live verify in İYS sandbox the token body (JSON), consent errors and especially `GET …/consents/changes?after=&limit=` (path / shape inferred from integrator libraries; a failure only sets `iys_settings.last_error`). Paraşüt has no public sandbox: test with a real company on a draft day; e-Fatura `invoice_number` may be missing (job fails with a clear message, staff records it by hand).
- Integration tests that resolve customers or newsletter need `registerIys(root)` (their consent writers depend on `IysQueueToken`).
- iyzico code matches the docs (2026-11-16) and passes fake-server tests, but is NOT verified against the real sandbox yet: run `npm run iyzico:sandbox` (pay once with a test card, then `--token=… --refund=…`) before going live. If the CF response signature check fails there, every card payment would stay unsettled — fix `checkoutFormSignatureData` first. Webhook `X-IYZ-SIGNATURE-V3` is only sent after iyzico enables it for the account.
- `ux_payment_config_active` (one active `payment_configs` row per provider): in one batch deactivate the others BEFORE activating, else UNIQUE fails. `integration_secrets` UNIQUE has a NULL column → no upsert; delete + insert. `buy_x_get_y` exists in schema but not offered in panel. Date filters use UTC day bounds in places (display Europe/Istanbul).
- Seed `admin@nova.local` password undocumented → use `admin:create`. Container first start on an empty DB loads seed.sql; `SEED_ON_INIT=false` (prod template default) loads only the part above `-- @demo-data-below` (roles/permissions/core config — required, else no `role_admin` and `create-admin` has nothing to grant). New base reference rows go ABOVE that marker, demo rows below.
- Media: a new upload folder goes into `MEDIA_FOLDERS` only — `STORAGE_KEY_PATTERN` (/assets whitelist) is derived from it. A new table/setting that stores a media id must be added to `D1MediaRepository.isReferenced`, else `release()` deletes an image still in use (SET NULL FKs blank silently).
- Changing a CHECK (new enum value) = table rebuild in a migration marked `-- foreign_keys: off` (runner turns FKs off around it and runs `PRAGMA foreign_key_check` before COMMIT; recreate the table's indexes + triggers in the migration because schema.sql ran first). Example `2026-11-15-cash-on-delivery.sql`. `PRAGMA writable_schema` does not work: node:sqlite (≥25.1) runs in defensive mode. Tests with `FixedClock` must `advanceMinutes` between saves guarded by `updated_at`.
- `campaigns.kind` CHECK cannot change on a live DB (rebuild = DROP → FK CASCADE deletes coupons/targets). New offer types go in `campaigns.offer_type` and are stored with an existing `kind` (`storageKind()`). Add columns only with `ALTER TABLE … ADD COLUMN` (column-level CHECK only) in a `db/migrations/` file.
- Seed `cmp_3al2` is active now: integration tests that need a campaign-free cart must deactivate it (`services.test` relies on its 3-unit lock).
- Client components must not import a module's `index.ts` for values (it pulls DI/database code into the bundle): import pure `domain/*` files, and only `import type` from the index.
- Zod 4: `z.record(z.enum(...), v)` is exhaustive (every key required) — use `z.partialRecord` for optional keys.
- Framing: storefront pages allow same-origin frames (Vitrin › Önizleme: `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`); `/admin` stays `DENY` / `'none'` (next.config.ts later entry + src/proxy.ts). Keep both in sync.
- Trigger codes (`RAISE(ABORT,'insufficient_stock')` …) reach application code as raw errors from `UnitOfWork.commit`; they become AppErrors only in `route()`. Branch on `isAppError(e) ? e.code : databaseErrorCode(e)`.
- A column added by `ALTER` can't get an index anywhere: not in schema.sql (old DBs fail before migrate), not in its own migration (`test_schema.py` #51 runs every migration probe on a fresh schema DB, so a fresh DB would never get it). Enforce uniqueness in the use case (e.g. `products.model_code`).
- Marketplaces accept only https raster images (no SVG; seed demo images are SVG → filtered out in `buildTrendyolItem`). Trendyol stage needs IP whitelisting; identical price/stock request within 15 min is rejected (we hash and skip unchanged).
- Bulk Excel files are never uploaded; never add a server-side xlsx parser. Remote fetches only via `RemoteFetcher` (SSRF guard).
- Social AI Marketing (Meta): endpoints / scopes / payloads follow developers.facebook.com as of 2026-11-16 (Graph `META_GRAPH_VERSION` v27.0) but are tested only against fixtures and fakes — before going live verify with a real app: Embedded Signup popup (`FB.login` + `WA_EMBEDDED_SIGNUP` message), the Instagram webhook signature secret (code accepts the Meta app secret OR the Instagram app secret), the human agent tag (`messaging_type: MESSAGE_TAG`, `tag: HUMAN_AGENT` — syntax not shown on the Instagram docs page) and that a WhatsApp number onboarded by Embedded Signup can send without `/register` (not called: it would set the number's two-step PIN). Meta App Review is required for real customers. History / pending messages are ordered by `rowid`, never `created_at` (ties within a millisecond reorder the conversation). The bot mutates its `messages` array between `AiChat.turn` calls — fakes must copy it to assert on a request.
- `db/migrations/2026-11-16-social-ai.sql` repeats the `social_ai_*` DDL of schema.sql (so `db:migrate` alone upgrades a database); `test_schema.py` #63 compares both texts object by object — a later change to those tables must be made in schema.sql AND as a new ALTER migration, never by editing that file's CREATE statements only. New tables also go into `db/drop_all.sql` (children first).
- GraphQL SDL lives in a JS template literal (`src/server/graphql/schema.ts`): `\"` there becomes a bare `"` → SDL parse error at startup (every route importing the graph 500s). Keep descriptions free of quotes; `npm run test:storefront` parses the schema.
- eslint `react-hooks/set-state-in-effect` is on: no synchronous setState in an effect body (also not via a called helper that sets state before its first await). Load data with `api.get().then(…)` + a `live` flag inside the effect (see `AuditDetailDrawer`), reset state on prop change during render (`if (id !== shownId) { setShownId(id); … }`), and pass stable (`useCallback`) `onClose` props into drawers whose effect depends on them.
- Thumbnail SQL over `product_media` (cards, cart, orders, mails, marketplaces, reviews) must join `media_assets m ON … AND m.mime_type LIKE 'image/%'`: galleries can hold MP4 videos, and a query without the filter can return a video URL as an image. Page CSP `media-src` is `'self' blob:` (blob = upload preview in the panel); a video host would have to be added there.
- Meilisearch: a NEW product field that should be searchable / rank must be added in three places — `D1SearchRepository` DOCUMENTS SQL, `SearchDocument`, `productIndexSettings` (the settings hash then re-sends settings; documents need a rebuild). Change capture does not log brand / category renames: they reach the index with the daily full rebuild or “Dizini yeniden kur”. Compose `environment:` beats `env_file:` — the prod `meilisearch` service gets ONLY `MEILI_MASTER_KEY` through interpolation from the server's `.env` (written by `deploy.sh`); do not give it `.env.production`. Minor image upgrades cannot read the old `meili-data` volume: remove the volume, the next sync rebuilds.
- Integration tests run on a `FixedClock` but seed rows get the real time from column defaults (`strftime('now')`): once the wall clock passes the fixed test time, "newest first" orderings flip. Pin seed timestamps in the test (see `tests/integration/wishlist.test.ts`) instead of trusting the run hour.
- A recursive `useCallback` (a toast action calling the callback that created it) fails `react-hooks/immutability`: call the latest version through a ref updated in an effect (see `WishlistProvider` undo).
- Timestamp triggers (`trg_ts_<table>_ins` / `_upd`, end of schema.sql) stamp nullable `created_at` / `updated_at` columns that were added late. On an old database schema.sql creates the triggers BEFORE the columns exist, so the migration that adds them is named `0000-row-timestamps.sql` to sort first; a new table joining this scheme needs its ALTERs in a migration that also sorts before any migration updating that table. Never add such a trigger to a table with a `BEFORE UPDATE … RAISE` guard (order_items, audit_logs, …) or with change-capture `AFTER UPDATE` triggers without a column list.
- Index on a migrated column → `db/late-indexes.sql`, never schema.sql (the older rule "can't get an index anywhere" is solved by that file). Before adding an index check the table's PRIMARY KEY / UNIQUE constraints: they already are indexes (`product_categories(product_id, category_id)`, `product_attribute_values(product_id, attribute_id, value_index)`).
- e2e (2026-11-17): 7 specs fail on the committed tree too, all on storefront steps written before the cookie banner / footer newsletter form existed (banner intercepts clicks, `getByLabel("E-posta")` matches two fields). Not caused by panel work; the specs need updating.
- `notify.success` fires balloons in the panel: do not call it for passive / repeated events (autosave, polling) — use `notify.info`.
- Kafka REST Proxy (cp-kafka-rest 7.9) offset commit: `POST …/offsets` must carry NO body to mean "commit everything fetched"; a `{}` body → HTTP 500 (NullPointerException on `getOffsets()`), the consumer never commits and re-reads the same records every cron minute. Only shows once a topic holds messages (empty DB = silent). Guarded in `marketplaces.test.ts`.
- Append-only ledgers (`audit_logs`, `order_events`, `inventory_movements`) + matched `bank_transfers` CHECK keep their actor: a staff/admin user cannot be hard-deleted once it acted. Retire it instead (delete credentials / roles / staff profile, `status=suspended`, unreachable e-mail).
