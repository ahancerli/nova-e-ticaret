# Pitfalls
- iCloud duplicates: project lives on iCloud-synced Desktop; files like `page 2.tsx`, `api 2.ts`, `module 2.ts`, `* 2.test.ts` appear (74 identical copies removed in commit a941400, 2026-11-04; they reappear while the repo stays on iCloud). They are stale copies — never edit/import them; search results may show both. `tsconfig` only ignores `.next/**/* ?.ts`.
- `globals.css` must keep `@import "tailwindcss" source("..")` (scan src/ only): default root scan watches `.next/dev/logs` (written every request by Next 16) → endless dev reloads / e2e hangs.
- `npm run dev` and local `docker compose` share `data/nova.db`: never run both (SQLite locks over Docker Desktop file sharing are unreliable). After schema-changing `db:*` commands restart the dev server.
- Production without SESSION_SECRET/SECRETS_MASTER_KEY/CRON_SECRET → `ConfigError` at startup. `SECRETS_MASTER_KEY` must stay the same across moves, else sealed SMTP/AI/marketplace keys are unreadable.
- Standalone tracing: runtime fs paths built from `process.cwd()` / variables must carry `/* turbopackIgnore: true */` (see `src/server/env.ts`, `FsObjectStorage`), else Next copies the whole project (incl. `data/`, `.env*`) into `.next/standalone`. Packages imported by `scripts/*.mjs` inside the container must be in `serverExternalPackages`.
- Client IP = `X-Real-IP` (set by Caddy); the app container must never publish a port in production (header would be spoofable). Local Docker has no Caddy → all clients share one rate-limit IP.
- SSRF: `SafeFetcher` DNS-resolves every hop and refuses private IPs (app shares the Docker network with unauthenticated Kafka REST). Keep it; tests inject a resolver as 2nd ctor arg.
- SQLite ≥3.51: correlated subquery `ORDER BY` can't reference outer columns; keep outer refs in `WHERE`.
- `schema.sql` is fully re-runnable (tables, indexes, triggers all `IF NOT EXISTS`; catalog rows upsert) → `db:schema:*` adds new tables to an existing DB, but column changes don't apply (need `ALTER TABLE`). Keep new DDL idempotent.
- Outgoing mail = shop SMTP account (`modules/mail`, panel Entegrasyonlar › E-posta). Every send goes through `SmtpMailSender`, which writes `mail_deliveries` (panel "Son gönderimler") — background sends (reset mail in `after()`) are only visible there. SMTP failures → MailErrors only via `classifySmtpFailure` (stage + reply); transport errors must never include the sent command (AUTH carries the password). Panel "Parolamı unuttum" e-mails the reset link (identity `RequestPasswordReset`, run in `after()` for no enumeration); raw tokens never go to DB/outbox. Without SMTP the link is logged only when not production. Invite links are still shown to the admin. Gmail needs an app password. Many VPS block outbound port 25 → use 465/587.
- iyzico refund endpoint, webhook V3 signature and the panel key test (`IyzicoBinProbe`, `/payment/bin/check`) not sandbox-verified.
- `ux_payment_config_active` (one active `payment_configs` row per provider): in one batch deactivate the others BEFORE activating, else UNIQUE fails. `integration_secrets` UNIQUE has a NULL column → no upsert; delete + insert. `buy_x_get_y` exists in schema but not offered in panel. Date filters use UTC day bounds in places (display Europe/Istanbul).
- Seed `admin@nova.local` password undocumented → use `admin:create`. Container first start on an empty DB loads seed.sql (demo data) unless `SEED_ON_INIT=false`.
- Media: a new upload folder goes into `MEDIA_FOLDERS` only — `STORAGE_KEY_PATTERN` (/assets whitelist) is derived from it. A new table/setting that stores a media id must be added to `D1MediaRepository.isReferenced`, else `release()` deletes an image still in use (SET NULL FKs blank silently).
- `campaigns.kind` CHECK cannot change on a live DB (rebuild = DROP → FK CASCADE deletes coupons/targets). New offer types go in `campaigns.offer_type` and are stored with an existing `kind` (`storageKind()`). Add columns only with `ALTER TABLE … ADD COLUMN` (column-level CHECK only) in a `db/migrations/` file.
- Seed `cmp_3al2` is active now: integration tests that need a campaign-free cart must deactivate it (`services.test` relies on its 3-unit lock).
- Client components must not import a module's `index.ts` for values (it pulls DI/database code into the bundle): import pure `domain/*` files, and only `import type` from the index.
- Zod 4: `z.record(z.enum(...), v)` is exhaustive (every key required) — use `z.partialRecord` for optional keys.
- Framing: storefront pages allow same-origin frames (Vitrin › Önizleme: `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'`); `/admin` stays `DENY` / `'none'` (next.config.ts later entry + src/proxy.ts). Keep both in sync.
- Trigger codes (`RAISE(ABORT,'insufficient_stock')` …) reach application code as raw errors from `UnitOfWork.commit`; they become AppErrors only in `route()`. Branch on `isAppError(e) ? e.code : databaseErrorCode(e)`.
- A column added by `ALTER` can't get an index anywhere: not in schema.sql (old DBs fail before migrate), not in its own migration (`test_schema.py` #51 runs every migration probe on a fresh schema DB, so a fresh DB would never get it). Enforce uniqueness in the use case (e.g. `products.model_code`).
- Marketplaces accept only https raster images (no SVG; seed demo images are SVG → filtered out in `buildTrendyolItem`). Trendyol stage needs IP whitelisting; identical price/stock request within 15 min is rejected (we hash and skip unchanged).
- Bulk Excel files are never uploaded; never add a server-side xlsx parser. Remote fetches only via `RemoteFetcher` (SSRF guard).
- GraphQL SDL lives in a JS template literal (`src/server/graphql/schema.ts`): `\"` there becomes a bare `"` → SDL parse error at startup (every route importing the graph 500s). Keep descriptions free of quotes; `npm run test:storefront` parses the schema.
- eslint `react-hooks/set-state-in-effect` is on: no synchronous setState in an effect body (also not via a called helper that sets state before its first await). Load data with `api.get().then(…)` + a `live` flag inside the effect (see `AuditDetailDrawer`), reset state on prop change during render (`if (id !== shownId) { setShownId(id); … }`), and pass stable (`useCallback`) `onClose` props into drawers whose effect depends on them.
