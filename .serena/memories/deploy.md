# Deploy runbook (production server)
- Server: Oracle Cloud VM (ARM A1.Flex, Ubuntu), SSH user `ubuntu`, app in `/opt/nova`. Host + key are in `deploy/.deploy.env` (`DEPLOY_HOST=…`, `DEPLOY_SSH_KEY=…` → `deploy.sh` passes it to ssh/scp/rsync; the file also holds the server notes as comments; gitignored and never rsynced — repo is public, never put the IP/user in tracked files). Site URL = `PUBLIC_SITE_URL` in `.env.production` (temporary `*.sslip.io` until the customer gives a domain).
- Deploy: `npm run deploy` (reads `deploy/.deploy.env`). Long build on the server: run it with output to a scratchpad log, timeout ≥ 10 min, then `tail` the log. Success = `✓ deployed` + `docker compose ps` all healthy. Only the source + `.env.production` are sent; DB and uploads stay in the server's `nova-data` volume.
- Before: `ssh -o BatchMode=yes $DEPLOY_HOST 'cd /opt/nova && docker compose ps'`. `Permission denied (publickey)` = key not loaded in ssh-agent (e.g. after reboot): ask the user to `ssh-add` their key (or check `~/.ssh/config` still maps the host to `~/.ssh/oracle_nova`); never try other keys/users.
- After, verify the live code: `curl https://<site>/api/health` → 200; a code-specific probe if the change is visible over HTTP (e.g. POST `/api/orders/lookup` with a fake order → message ends "onay e-postanızdan kontrol edin" since 2026-11-19).
- Server shell: `ssh $DEPLOY_HOST 'cd /opt/nova && docker compose <ps|logs -f app|restart app|exec -T app node scripts/<x>.mjs>'` (server `.env` sets COMPOSE_FILE to the prod files). Read-only DB peek: `docker compose exec -T app node -e` with `node:sqlite` `DatabaseSync('/data/nova.db',{readOnly:true})`.
- Admin for the customer: `docker compose exec app node scripts/create-admin.mjs <email> "<name>"` (password prompt → needs an interactive `ssh -t`, run by the user).
- `SEED_ON_INIT` only acts on an EMPTY database (fresh volume). Current prod server (new VM since 2026-11-21, 4 OCPU / 24 GB, Ubuntu 24.04, key `~/.ssh/oracle_nova`). On 2026-11-21 the LOCAL dev DB + `data/uploads` were copied to prod on purpose (customer demo): admin@nova.local retired (suspended, `retired-u_admin@nova.invalid`, no credentials/role — it cannot be hard-deleted: append-only ledgers + matched bank_transfers keep the actor), sessions/rate limits/tokens cleared, pending outbox closed, all `*_ciphertext/_nonce/_auth_tag` re-sealed from the local to the prod `SECRETS_MASTER_KEY` (keys differ). Local demo/test users are therefore on prod; the test account's role_admin was removed the same day, so prod had NO admin until the user runs `create-admin`. Pre-import backup: `/data/backups/pre-import-*.db`. Search index self-heals (empty index + published products → rebuild within a minute).
- Customer domain switch: set `DOMAIN`, `PUBLIC_SITE_URL`, `ACME_EMAIL` in `.env.production` (DNS A record → server IP first; Caddy gets the certificate), redeploy. Company info / payment / SMTP / cargo / CAPTCHA are entered by the customer in the panel, not in env.
- One-time server prep (already done): `deploy/server-setup.sh` (`mem:suggested_commands`). Off-site backup: litestream container runs but `LITESTREAM_*` is empty → idle; `SENTRY_DSN` / `HEARTBEAT_URL` empty.
