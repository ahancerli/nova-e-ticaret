# Deploy runbook (production server)
- Server: Oracle Cloud VM (ARM A1.Flex, Ubuntu), SSH user `ubuntu`, app in `/opt/nova`. Host is in `deploy/.deploy.env` (`DEPLOY_HOST=…`, gitignored — repo is public, never put the IP/user in tracked files). Site URL = `PUBLIC_SITE_URL` in `.env.production` (temporary `*.sslip.io` until the customer gives a domain).
- Deploy: `npm run deploy` (reads `deploy/.deploy.env`). Long build on the server: run it with output to a scratchpad log, timeout ≥ 10 min, then `tail` the log. Success = `✓ deployed` + `docker compose ps` all healthy. Only the source + `.env.production` are sent; DB and uploads stay in the server's `nova-data` volume.
- Before: `ssh -o BatchMode=yes $DEPLOY_HOST 'cd /opt/nova && docker compose ps'`. `Permission denied (publickey)` = key not loaded in ssh-agent (e.g. after reboot): ask the user to `ssh-add` their key; never try other keys/users.
- After, verify the live code: `curl https://<site>/api/health` → 200; a code-specific probe if the change is visible over HTTP (e.g. POST `/api/orders/lookup` with a fake order → message ends "onay e-postanızdan kontrol edin" since 2026-11-19).
- Server shell: `ssh $DEPLOY_HOST 'cd /opt/nova && docker compose <ps|logs -f app|restart app|exec -T app node scripts/<x>.mjs>'` (server `.env` sets COMPOSE_FILE to the prod files). Read-only DB peek: `docker compose exec -T app node -e` with `node:sqlite` `DatabaseSync('/data/nova.db',{readOnly:true})`.
- Admin for the customer: `docker compose exec app node scripts/create-admin.mjs <email> "<name>"` (password prompt → needs an interactive `ssh -t`, run by the user).
- `SEED_ON_INIT` only acts on an EMPTY database (fresh volume). The current prod DB was created 2026-11-18 with `true` → holds demo catalog + demo users (`admin@nova.local`, `musteri@nova.local`, `@example.com` staff) until cleaned; `.env.production` now has `false` (base data only, see `mem:pitfalls`).
- Customer domain switch: set `DOMAIN`, `PUBLIC_SITE_URL`, `ACME_EMAIL` in `.env.production` (DNS A record → server IP first; Caddy gets the certificate), redeploy. Company info / payment / SMTP / cargo / CAPTCHA are entered by the customer in the panel, not in env.
- One-time server prep (already done): `deploy/server-setup.sh` (`mem:suggested_commands`). Off-site backup: litestream container runs but `LITESTREAM_*` is empty → idle; `SENTRY_DSN` / `HEARTBEAT_URL` empty.
