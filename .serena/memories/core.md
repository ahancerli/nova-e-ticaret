# nova — core map
Single-seller e-commerce: storefront (`/`) + admin panel (`/admin`) in one Next.js 16 app (standalone Node server) in Docker Compose: SQLite file via `node:sqlite` (`DATABASE_PATH`), uploaded media on disk (`MEDIA_DIR`), Kafka + Kafka REST proxy, scheduler container, Caddy in production. Runtime/deploy layout: README §2.
Code/identifiers English; UI text, Zod messages, docs Turkish. Money = INTEGER kuruş, VAT-inclusive (`*_minor`).

Authoritative docs (read the relevant section instead of rediscovering): `README.md` §3 folder map, §4 architecture rules (1–14), §4.1 core/route, §4.2 module layout, §4.3 frontend/errors, §5 module status, §6 admin UI kit, §7 flows (checkout, order state machine, outbox, shipping, media), §8 API table, §10 known pitfalls. `db/README.md`: data rules, triggers→error codes, status machines, audit/permission dictionaries. `db/schema.sql` = single DDL source (142 STRICT tables; table-count assert in `db/tests/test_schema.py`). Every table has a Turkish `-- TABLO:` line right after `CREATE TABLE … (` and every column a trailing Turkish `-- …` comment (stored in sqlite_master); new columns need one too — no `;` or `'` inside comments (wrangler splits on them). Human guide: `db/nova-veritabani-rehberi.pdf`. Reference-data upserts at its end: `integration_providers`, `ai_models`, `pricing_policy`, `review_settings` (insert-only). Column additions for existing DBs: `db/migrations/*.sql`, each starting with a `-- probe: SELECT …` line; `scripts/migrate.mjs` (`npm run db:migrate:<local|remote>`) applies a file only while its probe fails → safe to re-run. New columns are also written into the CREATE TABLE in schema.sql (fresh DBs); never index a migrated column in schema.sql (fails on old DBs before migrate).

## Source map
- `src/core/` framework-free base (errors, di, db/UnitOfWork, http/router, logging, runtime, security). Never imports server/modules.
- `src/server/app.ts` composition root: DI registrations, `route`, `resolveService`, `currentPrincipal`, `requireAdminPage`. `env.ts` = per-process bindings (one `SqliteDriver` + `FsObjectStorage`, cached on `globalThis.__novaRuntime`; tests put their in-memory DB there) + secrets from process.env; type `RuntimeEnv` in root `runtime-env.d.ts`. `sqlite-driver.ts` = D1-shaped `prepare/bind/all/first/run/batch` over node:sqlite (batch = sync `BEGIN IMMEDIATE…COMMIT`, statement cache). `src/server/graphql/` read-only storefront graph (SDL `schema.ts` + `rootValue` → storefront query services; `execute.ts` depth/token limits), served by `src/app/api/graphql/route.ts` inside `route()`.
- `src/modules/<m>/` business modules (domain/application/infrastructure/http/module.ts/index.ts); public surface = `index.ts` only.
- `src/modules/integrations/` third-party firms (SMS / cargo): catalog = `integration_providers` table (upserted at the end of `db/schema.sql`), adapters in `infrastructure/connectors/` (`defaultConnectors()`), `IntegrationRuntime` port used by shipping (booking + `/api/cron/shipping-sync`) and notifications (order SMS). A firm is selectable only if catalog row is `ready` AND a connector exists.
- `src/modules/ai/` single AI provider (OpenAI/Gemini/Claude): `ai_integration` row (sealed key) + model catalog `ai_models` (panel select; only listed non-retired models accepted). Clients in `infrastructure/ai-clients.ts` implement `generate` + `checkModel` (free models-endpoint lookup = health check); provider HTTP failures → `AiErrors` only via `classifyFailure`. Real-key check: `npm run ai:health`.
- `src/modules/pricing/` cart engine: stages product → cart → coupon → shipping (`stageOf` in `campaigns/domain/campaign.ts`), `pricing_policy` conflict strategy + max discount share, unit locks for non-stackable campaigns, floor price `variant_prices.min_price_minor`. `GetProductPromotions` = storefront badges + "Sepette ₺X" (decorated in storefront query services, not the read model). Campaign offer type = `COALESCE(offer_type, kind)`. 30-day lowest price rule: triggers `trg_price_history_*` keep `variant_price_history` (open row `lowest_prior_minor`); customer/marketplace reads use `shownCompareAtSql(vp)` from `@/modules/catalog`, never raw `compare_at_minor`; editor hint via `shownCompareAt` (`lib/product-rules`) + `EditorVariant.priceCaps`.
- `src/modules/bulk/` Toplu işlemler: `RowEngine` = one path for Excel tabs and XML/REST feeds (normalize → locate by key → patch editor payload → `CheckProductSave` dry run or Create/UpdateProduct). "Ürün ekle" variants: rows with the same model code = one product (`groupKeyOf`; `RowEngine.runCreate/createModel`, all-or-nothing, known model code → new variants of it), variant columns `RawRow.variant` (attribute code → option text, header by label/code/`Varyant:` prefix via `variantColumnOf`); browser keeps a model in one request (`features/bulk/sheet.ts` `chunkRows`). Images op keyed by a variant barcode/SKU writes that variant's photos. Pure: `domain/xml.ts` (safe parser, no DOCTYPE/ENTITY), `domain/xlsx.ts` (browser .xlsx reader/writer), `domain/feed.ts` (list detection, field paths, auto-mapping), `domain/url.ts` (SSRF rules). `SafeFetcher` (https, redirects re-checked, size/time caps). Feeds sync in slices (`RunFeedSlice`, cron `/api/cron/feeds-sync`).
- `src/modules/catalog/` also owns the generic variant system: `domain/attribute.ts` (`ATTRIBUTE_ROLES` variant vs spec = `is_variant_axis`; types, display styles dropdown/swatch/button, `variesMedia` axis (Renk) = photos per value; `ATTRIBUTE_TEMPLATES` incl. spec templates (Kapasite, Materyal: capacity-like differences are separate products, not variants); `findOption` text→option; GS1 `ean13`/`classifyBarcode`), attribute commands + `/api/admin/attributes`, barcode prefix + sequence (`barcode_sequences`, `GenerateBarcodes`). Panel Katalog › Özellikler & varyantlar. Variant photos = `product_media.variant_id` rows (input `variants[].media`, never `is_primary`; rewritten each save after variants; detached/deleted product media released incl. variant photos). `products.model_code` (Trendyol productMainId, upper-case, uniqueness checked in plan — no index) → marketplace `productMainId` = model › manufacturer code › slug.
- `src/modules/messaging/` integration bus: CDC triggers `trg_ccl_*` (end of schema.sql) → `catalog_change_log` → `RelayCatalogChanges` (cursor `integration_relay_state`) → `MessageBus` topics `${KAFKA_TOPIC_PREFIX}.catalog.{product-info,stock,price,images}` + `.marketplace.orders`. Bus = `KafkaRestBus` (Kafka REST Proxy v2; Docker: `http://kafka-rest:8082`) when `INTEGRATION_BUS=kafka`, else `D1MessageBus` (SQLite `integration_messages` + consumer offsets). `D1*` class/file names are historical = plain SQL repositories over the Database port. A new catalog table that affects marketplaces needs a CDC trigger.
- `src/modules/marketplaces/` (Entegrasyonlar › Pazaryerleri): connection = one seller account (sealed keys), mappings (category/brand/attribute/value), listings per variant (barcode = marketplace key), `marketplace_pending` queue per kind (content/stock/price, each own interval), `MarketplaceSync` (consume bus → queue → push; batch results; approvals; order pull with 2h overlap watermark) and `ImportMarketplacePackage` (exactly-once: `marketplace_orders` PK + checkout idempotency key; channel cart per connection; `orders.sales_channel`). Only Trendyol client so far (`infrastructure/trendyol-client.ts`); new marketplace = client behind `MarketplaceClient` + `MARKETPLACES[k].ready`. Cron `/api/cron/integrations` every minute (relay + sync + order import). Tests swap the client via `MarketplaceClientFactoryToken`.
- `src/modules/reviews/` product reviews & ratings (Trendyol-style): customer `SubmitReview` (one per customer+product, edit restarts moderation; `review_settings`: purchase required, anonymity, min length, blocked words, mode `manual` | `auto_trusted`) → `pending` + panel notification in the same UoW → `ModerateReviews` (approve/reject(reason)/hide, bulk ≤50, guarded, dismisses `review.pending` notifications, audit `review.*`), `ReplyToReview` (public), `ContactReviewer` (e-mail via MailSender after commit → `review_contacts.delivery`; shown under Hesabım; phone/note internal). Only `approved` counts (cards/detail rating subqueries). Shop reads: SSR first page + GraphQL `reviews`; writes REST. Panel `/admin/yorumlar` (perm `reviews.moderate`).
- `src/modules/notifications/` = customer order SMS (`notifications.ts`, `registerNotifications()`) + panel notifications (`registerPanelNotifications(c)`): `NOTIFICATION_TYPES` catalogue (type → permission, severity, defaults), `NotificationPublisher.statements()` for producers' UoW (dedupe key, rules: in-app / e-mail via outbox `admin_notification.email`), per-staff read/archive state, personal mutes, rules (`settings.write`). Outbox producers: `order.placed`, `order.payment_after_cancel`. Bell = `features/notifications/NotificationBell` (polls summary), page `/admin/bildirimler`. New notification type = entry in `NOTIFICATION_TYPES` (+ zod enum follows).
- `src/modules/consent/` cookie consent (KVKK banner, revision, proof rows `cookie_consents`) + tracking tags (GA4, GTM, Google Ads, Meta, TikTok, Clarity, Yandex; code catalog `domain/tags.ts`) + `CommerceEvent` vocabulary + server-side purchase (GA4 MP / Meta CAPI on outbox `order.paid`); browser side `src/features/consent` (`ConsentRoot` in storefront layout, adapters, `track()`). Details/decisions: `mem:consent`.
- `src/modules/captcha/` bot protection (panel Ayarlar › Bot koruması `/admin/ayarlar/bot-korumasi`, perm `settings.write`): hosted providers only (Turnstile default, reCAPTCHA v3 scored) — single row `captcha_settings` (sealed secret, `forms` JSON, `verified_at`). Core port `CaptchaGuard` (`CaptchaGuardToken`) behind `route({ captcha: "<form>" })` (after body validation): off/unselected = no-op, no token `captcha_required`, rejected/low score/other form's action `captcha_failed`, provider down or secret unreadable = fail open + log. Switching on / changing keys while on needs a widget token solved in the panel with those keys (server verifies) so a wrong site key can't lock logins. Browser: storefront layout `CaptchaProvider` + `useCaptcha(form)` (`features/captcha/useCaptcha.tsx`: `slot`, `await headers()` → `X-Captcha-Token`, `reset()` after each attempt). Protected: signup, storefront login, forgot, review. Tests swap `CaptchaVerifierToken`.
- `src/modules/geo/` reference data `geo_countries` (245, phone rules from libphonenumber mobile metadata, `has_regions`) / `geo_provinces` / `geo_districts` (TR 81 / 973), upserted at the end of `db/schema.sql` (generated once, not hand-edited). `GeoDirectory.phone(path, raw, country?)` → E.164 (national or +intl input) and `.region(path, {countryCode, province, district})` → canonical TR names; signup, address book and `ConfirmCheckout` call them (phone schemas only cap length). Pure `domain/geo.ts` shared with the browser; UI `src/features/geo` (`SearchSelect` searchable list with flags, `PhoneField`, `RegionFields` → hidden inputs for plain forms). Flags = static `public/flags/<iso>.svg`. Addresses/orders store `country_code`; iyzico gets the English country name. Integration tests that resolve checkout/customers/addresses need `registerGeo(root)`.
- `src/server/error-reporter.ts` SDK-less Sentry-compatible reporter (`SENTRY_DSN`): JsonLogger `report` option gets every `error` line (original error via `RAW_ERROR` symbol field — never in the log line), `src/instrumentation.ts` `onRequestError` (render errors), `/api/client-errors`. Rate-limited, fire-and-forget. Uptime: scheduler pings `HEARTBEAT_URL` (/fail when `/api/health` fails). Backups: prod `litestream` service (S3/R2, restores a missing DB before app starts) + daily `backup`.
- `src/features/shop/` storefront micro-frontend (SSR layout/home, listing, product (`ProductInfoTabs` SSR panels + `ProductTabs` client island, hash `#aciklama|#ozellikler|#degerlendirmeler`; `SimilarProducts` rail → `/urun/[slug]/benzer` via `GetSimilarProducts`: own/sibling category + shared specs + brand + price-band score), `reviews/` product reviews section + write dialog, `compare/` comparison list in localStorage (≤4, `useSyncExternalStore`) + dock + `/karsilastir?urunler=slugs` table + “Diğer sitelerle karşılaştır” coming-soon dialog, shared `ui/` card/price/grid/rail/Modal, `data/graph.ts` GraphQL client, `data/reviews-api.ts` REST writes); `(storefront)` routes import only `@/features/shop` (server entry).
- `src/features/<area>/` client screens + `api.ts` (typed fetchers); `src/components/{ui,admin}` shared UI w/o business logic; `src/lib/` isomorphic helpers (`api-client`, `order-rules`, `product-rules`, `money`, `toast`).
- `src/app/` route groups: `(storefront)`, `(admin)/admin`, `(admin-auth)`, `(admin-print)`, `api/` (JSON route handlers), `assets/[...path]` (media from `MEDIA_DIR`).
- `src/proxy.ts` per-request CSP nonce. `tests/{unit,integration,e2e}`.
