# nova — core map
Single-seller e-commerce: storefront (`/`) + admin panel (`/admin`) in one Next.js 16 app (standalone Node server) in Docker Compose: SQLite file via `node:sqlite` (`DATABASE_PATH`), uploaded media on disk (`MEDIA_DIR`), Kafka + Kafka REST proxy, scheduler container, Caddy in production. Runtime/deploy layout: README §2.
Code/identifiers English; UI text, Zod messages, docs Turkish. Money = INTEGER kuruş, VAT-inclusive (`*_minor`).

Authoritative docs (read the relevant section instead of rediscovering): `README.md` §3 folder map, §4 architecture rules (1–14), §4.1 core/route, §4.2 module layout, §4.3 frontend/errors, §5 module status, §6 admin UI kit, §7 flows (checkout, order state machine, outbox, shipping, media), §8 API table, §10 known pitfalls. `db/README.md`: data rules, triggers→error codes, status machines, audit/permission dictionaries. `db/schema.sql` = single DDL source (169 STRICT tables, 24 of them stamped by `trg_ts_*` triggers; table-count assert in `db/tests/test_schema.py`). Every table has a Turkish `-- TABLO:` line right after `CREATE TABLE … (` and every column a trailing Turkish `-- …` comment (stored in sqlite_master); new columns need one too — no `;` or `'` inside comments (wrangler splits on them). Human guide: `db/nova-veritabani-rehberi.pdf`. Reference-data upserts at its end: `integration_providers`, `ai_models`, `pricing_policy`, `review_settings`, `delivery_settings`, `iys_settings` (insert-only). Column additions for existing DBs: `db/migrations/*.sql`, each starting with a `-- probe: SELECT …` line; `scripts/migrate.mjs` (`npm run db:migrate:<local|remote>`) applies a file only while its probe fails → safe to re-run. New columns are also written into the CREATE TABLE in schema.sql (fresh DBs); never index a migrated column in schema.sql (fails on old DBs before migrate).

## Source map
- `src/core/` framework-free base (errors, di, db/UnitOfWork, http/router, logging, runtime, security). Never imports server/modules.
- `src/server/app.ts` composition root: DI registrations, `route`, `resolveService`, `currentPrincipal`, `requireAdminPage`. `env.ts` = per-process bindings (one `SqliteDriver` + `FsObjectStorage`, cached on `globalThis.__novaRuntime`; tests put their in-memory DB there) + secrets from process.env; type `RuntimeEnv` in root `runtime-env.d.ts`. `sqlite-driver.ts` = D1-shaped `prepare/bind/all/first/run/batch` over node:sqlite (batch = sync `BEGIN IMMEDIATE…COMMIT`, statement cache). `src/server/graphql/` read-only storefront graph (SDL `schema.ts` + `rootValue` → storefront query services; `execute.ts` depth/token limits), served by `src/app/api/graphql/route.ts` inside `route()`.
- `src/modules/<m>/` business modules (domain/application/infrastructure/http/module.ts/index.ts); public surface = `index.ts` only.
- `src/modules/integrations/` third-party firms (SMS / cargo): catalog = `integration_providers` table (upserted at the end of `db/schema.sql`), adapters in `infrastructure/connectors/` (`defaultConnectors()`), `IntegrationRuntime` port used by shipping (booking + `/api/cron/shipping-sync`) and notifications (order SMS). A firm is selectable only if catalog row is `ready` AND a connector exists.
- `src/modules/ai/` single AI provider (OpenAI/Gemini/Claude): `ai_integration` row (sealed key) + model catalog `ai_models` (panel select; only listed non-retired models accepted). Clients in `infrastructure/ai-clients.ts` implement `generate` + `checkModel` (free models-endpoint lookup = health check) + `converse` (tool use, provider independent: `AiChatMessage` user / assistant(+toolCalls, `raw` = provider's own content replayed unchanged inside one tool loop: Claude thinking blocks, Gemini thought signatures) / tool results); provider HTTP failures → `AiErrors` only via `classifyFailure`. Other modules use the port `AiChat` (`AiChatToken`: `status()`, `turn()`) — the key never leaves the ai module. Real-key check: `npm run ai:health`.
- `src/modules/social-ai/` Social AI Marketing (panel group Social AI Marketing: `/admin/social-ai/{whatsapp,instagram,konusmalar,bot-ayarlari}`, perms `social_ai.manage` / `social_ai.chat`): AI answers WhatsApp + Instagram DMs. Flow: `/api/webhooks/meta` (plain route; `X-Hub-Signature-256` vs any sealed app secret, GET verify token) → `ChannelAdapter` (`infrastructure/channels/{whatsapp,instagram}.ts`: `parse` → `InboundMessage`, `send`; registry `ChannelAdaptersToken`, new channel = one adapter) → `ReceiveWebhook` (idempotent on `UNIQUE (channel, external_id)`, sets `reply_due_at` = now + 4 s debounce) → `ProcessConversation` (row claim `locked_until`; run from the webhook's `after()` and the safety-net cron `/api/cron/social-ai` every 20 s) → `BotBrain` (≤6 tool rounds on `AiChat`; read-only tools in `domain/prompt.ts` `BOT_TOOLS`, executed against `StoreKnowledge` = `infrastructure/store-knowledge.ts` on storefront / content / questions / size-charts / delivery / settings queries) → out messages + outbox `social_ai.send` in one batch, sent right after commit by `DeliverMessage` (outbox = retry only; window check 24 h, Instagram staff replies 7 days with HUMAN_AGENT tag → else `blocked`). `FIXED_RULES` (AI honesty, no invented facts, customer text = data) is always in the system prompt — never make it configurable. Hand-off = conversation `handoff` + notification `social_ai.handoff`, bot silent until staff give it back; separate from `support` (that one needs a member account). One Meta app per shop (`social_ai_app`, secrets sealed as one JSON blob); connect = WhatsApp Embedded Signup (FB JS SDK popup; hosts in `META_SDK_CSP` → admin CSP in `src/proxy.ts`), Instagram Login (signed state cookie; `/instagram/callback` is a session-less bounce page because the admin cookie is SameSite=Strict, the channel page POSTs `/instagram/complete`), or manual ids + token. Daily cron `/api/cron/social-ai-daily`: 30-day hard delete (`RunRetention`, audit `social_ai.retention` with row counts only, written with `actor_id` NULL) + Instagram token refresh. Meta facts verified live 2026-11-17: Instagram webhooks arrive as `entry[].messaging[]` OR `entry[].changes[]` ({field, value: <event>}) — the adapter reads both; subscribed field is `messaging_referral` (singular, plural → code 100); the HUMAN_AGENT tag is sent only past the 24 h window (inside it Meta refuses the tag with code 10 until App Review); dev-mode apps get message webhooks only from accounts with an app role (Instagram Tester, invite accepted at instagram.com/accounts/manage_access).
